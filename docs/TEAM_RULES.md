# KrishiNirnay — Team Rules

## 1. GitHub Rules

- Do not delete another member's work.
- Commit changes frequently.
- Use clear commit messages.
- Pull the latest changes before starting work.
- Do not make unnecessary changes to another member's files.

## 2. Branch Rules

Each member should work on their own feature branch.

Examples:

feature/frontend-dashboard
feature/farmer-form
feature/backend-api
feature/recommendation
feature/data
feature/integration

Do not work directly on main unless approved by the team lead.

## 3. Commit Messages

Use clear commit messages.

Examples:

Add farmer input form

Add crop recommendation API

Add crop dataset

Connect recommendation API

Fix market calculation

Avoid messages such as:

test

asdf

changes

final final

final2

## 4. Communication

If a member is blocked for more than 30 minutes, inform the team.

Do not stay stuck silently.

## 5. API Rules

The API contract must be followed by all team members.

Do not change request or response formats without informing the team lead.

## 6. MVP Rules

The team will prioritize MVP features.

No major new feature should be added until the core MVP is working.

## 7. Integration Rules

Before merging a feature:

- Test it locally.
- Make sure existing features still work.
- Inform the integration lead.

## 8. Team Goal

The goal is not to produce the most code.

The goal is to produce a working end-to-end demonstration.
